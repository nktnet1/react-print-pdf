## Issues with Node.js modules

Use the default `react-print-pdf` entrypoint in Node.js, SSR, and build-time document generation:

```ts
import { compile, PageBreak } from "react-print-pdf";
```

For browser-only usage, the explicit client entrypoint is also available:

```ts
import { PageBreak } from "react-print-pdf/client";
```

The package does not include or require a hosted server. `compile()` produces HTML locally in your application.

If you mount the components directly in a browser without `compile()`, also import `react-print-pdf/dist/index.css` in the app's client entrypoint. The build extracts the component CSS into that separate, exported file. Compiled HTML already contains those styles and does not need the additional import.

## Next.js or Vercel reports a missing Tailwind module

Current React Print PDF releases compile Tailwind from the package bundle. They do not load Tailwind from your application's `node_modules` directory at runtime, so `compile()` can be used from a Next.js Server Component or Route Handler without installing Tailwind separately just for React Print PDF.

Older upstream releases used a browser JIT package together with deep `node_modules/tailwindcss/...` imports. Those filesystem assumptions could work locally and then fail after a serverless bundler traced or relocated the deployment files. Upgrade rather than adding output-file tracing rules for those old internal paths.

For a Route Handler, keep PDF work on the Node.js runtime:

```ts title="app/api/report/route.ts"
export const runtime = "nodejs";
```

`compile()` only produces renderer-ready HTML and does not launch Chromium. React Print PDF and Tailwind styles are inlined; assets that your document references still need URLs the renderer can reach. If you also use `react-print-pdf/playwright` to create the PDF inside the function, the browser binary has its own deployment requirements; see the [Playwright integration](/docs/integrations/playwright). A separately deployed Gotenberg renderer avoids shipping Chromium with the Next.js function.

## Vite warns that `stream` or `events` was externalized

You should not need Node.js `stream` or `events` polyfills for React Print PDF. Older versions pulled in `@emotion/server` for `compile(..., { emotion: true })`; that package depends on legacy Node stream utilities and caused Vite to emit browser-compatibility warnings even when the Emotion path was not being used.

React Print PDF now collects Emotion's generated CSS directly from an isolated Emotion cache, so `@emotion/server` is no longer a runtime dependency. If you still see those warnings after upgrading, inspect your application's dependency graph for another package that imports `@emotion/server`, `html-tokenize`, `multipipe`, or `through`.

## `gap` or `justify-evenly` looks different in the PDF

React Print PDF keeps Tailwind's standard flexbox output, including `gap`, `row-gap`, `column-gap`, and `justify-content: space-evenly`. The final layout is still determined by the PDF renderer's CSS engine.

The built-in [Playwright](/docs/integrations/playwright) and [Gotenberg](/docs/integrations/gotenberg) integrations use Chromium, where these flexbox features are supported. If the same compiled HTML looks correct in a browser but different in a PDF produced by another renderer, check that renderer's support for CSS Box Alignment and flex gaps before replacing the utilities with manual margins.

This matters especially with older paged-media engines, which may accept flexbox while only partially supporting newer alignment and gap features. Upgrading the renderer or using one of the Chromium-backed integrations is preferable to changing the document layout to renderer-specific spacing hacks.

## Tailwind utilities are missing in a non-Chromium PDF renderer

The `Tailwind` component scopes its generated rules with CSS `@scope` to prevent separate theme regions from overriding one another. The compiled HTML therefore requires a renderer that implements CSS `@scope`. If an engine does not support it, those utilities can be ignored even though `compile()` succeeds. Check your renderer's CSS compatibility documentation, or use ordinary unscoped CSS for that document.
